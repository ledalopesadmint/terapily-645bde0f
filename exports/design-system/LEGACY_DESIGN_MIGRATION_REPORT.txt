================================================================================
LEGACY DESIGN MIGRATION REPORT
Terapily — Projeto antigo → Novo core (Supabase BYOS, Module Engine, Contracts)
Gerado: 2026-05-16
================================================================================

CONTEXTO
--------------------------------------------------------------------------------
Este projeto antigo deixa de ser o core principal da Terapily. Está sendo
transformado em "Legacy Design Reference System" — sua função única passa a ser
servir como FONTE DE VERDADE VISUAL para o novo core, que está sendo construído
do zero com:

  - Supabase BYOS (Bring Your Own Supabase)
  - auth/runtime novo
  - RLS nova
  - legal gate
  - workspace bootstrap transacional
  - boundaries rígidos client/server
  - service_role estritamente server-only
  - contracts tipados
  - Module Engine
  - registry architecture
  - PDF Engine 2.0 (desacoplada)
  - activity runtime desacoplada
  - foundation segura compliance-oriented

O runtime legado deste projeto NÃO é compatível com o novo core. Portanto:
não exportamos o app inteiro, não copiamos runtime, lógica, auth, stores,
arquitetura clínica, PDF runtime, hooks acoplados, nem estrutura Supabase
antiga. Apenas a CAMADA VISUAL.

5. RUNTIME LEGADO DETECTADO
================================================================================

Padrões de acoplamento problemáticos encontrados:

  (a) AppShell.tsx consome useAuth(), useQuery(getCurrentSubscription),
      hasRole() — visual misturado com lógica. Refator obrigatório no
      novo core: separar <AppShellLayout> visual de <AppShellContainer>
      que consome contexto.

  (b) Componentes brand importam <Link to="/" /> diretamente do TanStack
      Router. No novo core, abstrair via <BrandLink> agnóstico.

  (c) Landing (1855 linhas) tem CTAs apontando para rotas legadas
      (/signup, /login, /dashboard) que não existem no novo core.

  (d) Rotas _authenticated/* presumem AuthProvider legado, RLS antiga e
      tabelas patients/workspaces/audit_logs antigas. Toda a árvore
      _authenticated deve ser refeita no novo core.

  (e) src/start.ts registra attachSupabaseAuth como functionMiddleware —
      acoplado ao auth-attacher legado. Não migrar.

  (f) src/integrations/supabase/types.ts é auto-gerado pelo schema legado.
      Tipos do novo core serão regenerados contra schema BYOS novo.
