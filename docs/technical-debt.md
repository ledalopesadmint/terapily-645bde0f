## 1. Override de tipos para `@lovable.dev/cloud-auth-js`

**Origem.**
O arquivo `src/integrations/lovable/index.ts` é **auto-gerado pelo Lovable Cloud** (marcado `// This file is auto-generated by Lovable. Do not modify it.`). Ele declara o parâmetro `provider` como `"google" | "apple" | "microsoft" | "lovable"`, porém o tipo `OAuthProvider` exportado pelo SDK `@lovable.dev/cloud-auth-js` (v0.x) é apenas `"google" | "apple" | "microsoft"`. O resultado é um erro de TypeScript:

```
TS2345: Argument of type '"google" | "apple" | "microsoft" | "lovable"'
        is not assignable to parameter of type 'OAuthProvider'.
```

O erro **não foi introduzido pelo código do app** e não afeta o runtime — Google OAuth e email/senha funcionam normalmente. Trata-se de inconsistência entre o template gerado e a versão atual do SDK.

**Impacto.**
- `bunx tsc --noEmit` falhava antes do override.
- Build (`bun run build`) passava porque Vite não bloqueia em erro de tipo, mas o erro poluía o IDE/CI.
- Sem efeito sobre auth, banco, RLS ou migrations.

**Mitigação atual.**
Arquivo `src/types/lovable-auth-augmentation.d.ts` faz **override de tipos via `declare module`**, expandindo `OAuthProvider` para incluir `"lovable"` e mantendo as demais assinaturas idênticas ao SDK. Solução totalmente tipada:
- ❌ Sem `@ts-ignore`.
- ❌ Sem `any` amplo.
- ❌ Sem editar arquivo auto-gerado.
- ❌ Sem alterar auth, RLS, migrations ou config do Supabase.

**Condição de remoção.**
Quando o pacote `@lovable.dev/cloud-auth-js` publicar uma versão em que o tipo `OAuthProvider` inclua `"lovable"` (ou quando o template do Lovable Cloud parar de injetar `"lovable"` no arquivo gerado), basta:

1. Atualizar o pacote: `bun update @lovable.dev/cloud-auth-js`.
2. Conferir o tipo em `node_modules/@lovable.dev/cloud-auth-js/dist/index.d.ts`.
3. Deletar `src/types/lovable-auth-augmentation.d.ts`.
4. Rodar `bunx tsc --noEmit` para confirmar que não há regressão.

**Verificações pós-correção (executadas em 2026-04-27).**
- ✅ `bunx tsc --noEmit` sem erros.
- ✅ `bun run build` conclui (`✓ built in ~7s`).
- ✅ `src/integrations/lovable/index.ts` permanece intacto.
- ✅ `GoogleButton.tsx` continua chamando `lovable.auth.signInWithOAuth("google", …)`.
- ✅ Login email/senha (`supabase.auth.signInWithPassword`) inalterado.
- ✅ Callback `/auth/callback` inalterado.
- ✅ Nenhuma migration ou policy RLS tocada.
